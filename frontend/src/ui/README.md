# Shared presentation

- `styles/tokens.css` owns typography roles: page, section, subheading, body, small and caption; regular and strong weights. Use roles rather than choosing new font sizes/weights per view. Reader prose and font previews retain their user-controlled sizing and line spacing.
- `FeatureScaffold` owns page headings, descriptions and the optional `actions` slot. Keep page actions there instead of introducing a second header style.
- `AppDisclosure` owns the native `<details>/<summary>` interaction, chevron, focus treatment and content padding. Put the label in `#summary`. Use `v-model:open` or `@toggle` only when the feature needs open state (for example, lazy data loading). The component does not fetch, retain or discard feature data.
- Ordinary input/select/textarea values use body size and regular weight, independently of smaller or emphasized labels. This also avoids undersized mobile form text.
- Single-value selects retain native bindings and keyboard behavior. Start their children with `<component :is="'button'" type="button"><selectedcontent /></component>` before the options. This browser-owned display lets shared CSS truncate selected text without hiding the arrow; unsupported browsers retain their ordinary select. Vite/Vitest recognize `selectedcontent` as native markup. Workaround: Vue's current nesting validator still rejects the standard customizable-select button; `component :is="'button'"` renders that native element without introducing a Vue component instance. Once Vue updates its HTML nesting rules, ordinary `<button>` markup can replace the escape. Do not apply it to multiple/size listboxes.
- Shared picker CSS provides single-line options, a readable minimum width and viewport-constrained scrolling. Anchor fallbacks choose the side with more room, including above a bottom-edge trigger. Avoid fixed viewport-height caps that can overlap the trigger on short screens; no JS positioning or resize/scroll handlers are needed.
- `AppIcon` owns the small, static SVG vocabulary shared with the reader. Use icons alongside text selectively (reading, bookmarks, reparse and selected state), not on every action. Icons are decorative/hidden from assistive technology; the visible label supplies the accessible name.
- `AppButton` owns button semantics and busy/disabled state. `styles/controls.css` owns its appearance; navigational `RouterLink`s can use `app-button app-button--secondary` (or another existing variant) without pretending to be buttons.
- Use filled accent for the primary action, outlined paper for secondary actions, and transparent outlined quiet controls for lower-priority actions. Quiet does not mean invisible. Keep contextual/back/title links and navigation menus as links rather than making every destination a button. Feature CSS owns placement, not a second button skin.
- `BookDetailSection` exposes separate status/actions slots; BookDetailToc forwards the actions slot. Header actions wrap/right-align without coupling the presentation components to TXT routes. The preview heading/action row owns its alignment; never add blanket margins to its buttons. Desktop prose samples stretch to the chapter pane, while stacked mobile samples retain a bounded scroll area.
- `app-actions` provides wrapping, center-aligned action rows. Feature CSS may position the row or change its responsive layout; avoid duplicating its baseline gap/alignment.

Feature components own their data, mutations, polling and error recovery. Shared components own presentation and basic interaction only. Prefer a shared CSS rule for simple layout, a component for repeated markup/interaction, and no wrapper whose only job is passing calls through.
